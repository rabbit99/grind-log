# 計算規則

原則：**只儲存原始觀察值，所有指標都即時計算**。資料格式見 [format.md](format.md)。

本文件描述程式實際的算法。改動任何算法時，經驗條、人員效率表、記錄表、每日進度頁、CSV 要一起檢查，
因為它們共用這些函式。

## 基本取值

| 函式 | 規則 |
|---|---|
| `num(n)` | `Number(n)`。注意 `Number(null)`、`Number("")` 是 0，`Number("0x33")` 是 51 |
| `pctOf(s)` | `gainedPct` 轉數字，是有限數字就用它（`-0` 變成 `0`），否則當 0。認不得的值（`"5%"`）不能讓累計變成 NaN |
| `lvOf(s)` | `level` 是 `null` 或空白時是 `NaN`（代表「沒有等級」，不是 0 級），否則 `Number(level)`，所以 `"5%"` 也是 `NaN` |
| `numOrNaN(v)` | `null` 或 `""` 是 `NaN`，否則 `Number(v)` |
| `hoursOf(s)` | 起、迄都是有限數字時：`end >= start ? end - start : end + 24 - start`，也就是跨午夜加 24；否則是 0 |
| `billHoursOf(s)` | `billableHours` 是 `null`／`undefined`／`""` 時等於 `hoursOf(s)`，否則 `Number(billableHours)` |
| `levelInfo(lv)` | 等級表裡**第一列** `Number(level) === Number(lv)` 的列。所以等級空白的列會對到 Lv 0，`"0x33"` 會對到 Lv 51 |
| `workerOf(id)` | 人員表裡 `id === id` 的人員（嚴格相等） |
| `isOn(s)` | `enabled !== false`，缺欄位視為啟用 |
| `colorOf(id)` | 依人員在 `db.workers` 裡的**位置**取 `--w1`～`--w6`，循環使用；找不到人員時是灰色。刪掉前面的人員，後面的人員顏色會跟著變 |

## 一筆記錄的推導值：`derive(s)`

| 欄位 | 算法 |
|---|---|
| `hours` | `hoursOf(s)`，時段長度 |
| `billHours` | `billHoursOf(s)`，計費／有效時數 |
| `adjusted` | `billHours !== hours`，記錄表用金色標出 |
| `required` | `levelInfo(s.level)` 的升級經驗，找不到列是 0 |
| `units` | 獲得經驗：`required` 有值時是 `pctOf(s) / 100 × required`，否則 0 |
| `unitsPerHour` | 每小時經驗：`billHours > 0 ? units / billHours : 0` |
| `pctPerHour` | 每小時%：`billHours > 0 ? pctOf(s) / billHours : 0` |
| `cost` | 費用：`billHours × rate`。`rate` 在人員存在而且勾了「計費」時是 `Number(hourlyRate) \|\| 0`，否則是 0 |
| `costPerMUnit` | 每百萬經驗成本：`units > 0 ? cost / (units / 1e6) : 0` |
| `estimated` | 等級表那一列的可信度是 `"estimated"` |
| `worker` | `workerOf(s.workerId)`，可能是 `null` |

**效率和費用的分母都是計費時數，不是時段長度**。真人代練的時段含休息，休息既不計費也不產生經驗；
用時段長度去除，效率會被低估。

注意：

- `derive` 找等級用的是 `levelInfo(s.level)`，用 `Number()` 比對，**不是** `lvOf`。所以等級空白的記錄會對到 Lv 0，或等級空白的那列，照樣算得出經驗和花費，包括每日進度頁的「獲得經驗」「花費」。
  只有用 `lvOf` 的地方會把它當成「沒有等級」：經驗條的目前等級與本級記錄、每日進度頁的等級、獲得%、當前%。
- 等級表的升級經驗是認不得的文字時，`required` 是 `NaN`：記錄的經驗算成 0，但 CSV 的「該級升級經驗」那一格會輸出 `NaN`。

## 排序

- `sorted()`：日期**以字串比較**，同一天再依開始時間排序。開始時間不是有限數字的排最後。
  - 載入時日期都已經整理成 `YYYY-MM-DD`，所以字串順序就是日期順序。
  - 認不得的日期字串會依字串順序混在裡面。
- `activeSorted()`：`sorted()` 裡只留啟用的記錄。

經驗條、記錄表、CSV 都用這個順序。每日進度頁的逐日累計也用同樣的順序：先依日期，再依開始時間。
這樣浮點數加總的順序一致，最後一天的「當前%」才會跟經驗條的「本級已累積」逐位相同。

## 經驗條（本級）

1. `all` = 啟用的記錄，依 `sorted()` 排序。沒有任何啟用的記錄時，顯示「尚無記錄」或「所有記錄都取消啟用了」。
2. **目前等級** = 最後一筆**等級有效**（`lvOf` 是有限數字）的啟用記錄的等級。如果全部都無效，就用最後一筆的 `Number(level)`。
3. `cur` = 等級等於目前等級的所有啟用記錄，不分日期，日期認不得的也算。
4. 本級已累積 = `cur` 的 `pctOf` 總和。**負值照樣扣**，例如死亡掉經驗。
5. 色塊寬度 = `min(max(0, pct), 100)%`，負的畫成 0 寬。
6. 統計：
   - 本級時速 = Σ`units` ÷ Σ`billHours`。
   - 本級投入 = Σ`billHours` 小時，天數是 ÷ 24，是換算單位，不是日曆天數。
   - 本級花費 = Σ`cost`。
   - 累計花費 = 所有啟用記錄的 Σ`cost`，不分等級。

## 人員效率表

- 對 `db.workers` 裡的每一位人員，取啟用記錄中 `workerId` 等於他的記錄，加總 `billHours`、`pctOf`、`units`、`cost`。
- 每小時經驗 = units ÷ hours；每小時% = pct ÷ hours；每百萬經驗成本 = cost ÷ (units / 1e6)。
- 每百萬經驗成本顯示「—」的條件：
  - 各人員的列：算出來是 0 的時候。最常見的是不計費的人員（費用 0），units 是 0 時也是。
  - 合計列：只有總經驗是 0 時才顯示「—」；總費用是 0 時顯示「0」。
- 只列出時數 > 0 的人員。**找不到人員的記錄不會出現在這張表**；它們的費用是 0，經驗仍計入經驗條。
- 最佳每小時經驗標綠色。每百萬經驗成本在有費用（> 0）的人員中，最低標綠色、最高標紅色。
- 合計列是所有列出人員的加總，比率由加總值重新計算，不是把各列比率平均。

## 每日進度頁

見 [features/daily.md](features/daily.md)。演算法重點：

- **分組**：用 `normDate(date)` 分組。認不得的日期集中成最後一列「日期不明」。
- **補空白日**：第一天到最後一天之間，沒有記錄的日子也列出來。但首尾相差超過 3660 天時不補，因為通常是年份打錯。
- **一天的合計**：只算啟用的記錄。
  - 經驗、花費、計費時數直接相加。
  - 獲得% **依等級分開加總**。不同等級的 1% 代表的經驗量不同，不能相加。
- **當天的等級**：所有記錄（含停用）中有效等級的最小到最大，例如 `51→52`。
- **當前%**：當天結束時，各等級已累積的 %。
  - 跨所有日期，依日期、再依開始時間逐筆累加啟用記錄的 `pctOf`。
  - 日期不明的記錄不參與累計，所以如果目前等級有日期不明的記錄，最後一天的當前% 會跟經驗條的「本級已累積」不一樣。
- **「缺」標記**：等級 < 最高等級（啟用記錄中最大的有效等級），而且這個等級所有有日期的啟用記錄加總 < 99.5% 時標「缺」，代表有時段沒登錄。
  - 注意這裡用的是「最高等級」，跟經驗條的「目前等級」（最後一筆有效記錄的等級）不同。
  - 門檻是 99.5%，不是 100%：累積到 99.7% 的等級不會標「缺」。
- **獲得% 的「lv?」**：啟用、但等級無效（`lvOf` 是 NaN）的記錄，獲得% 自成一組。跟有效等級同一天時列成「lv?」一行；只有這一組時直接顯示數字。當天的等級欄只列有效的等級。

## 時間軸（每日進度頁的色塊）

- 位置用真實的起訖時間：`left = clamp(start, 0, 24) / 24`。
- 跨午夜（`end < start`，而且不是「剛好在 0 點結束」）只畫到 24 點，右端標 ↪。
- `end === 0 && start > 0`（例如 18 到 0）視為剛好在午夜結束，畫到 24 點，不算跨午夜。
- 計費時數和時段不同時照樣畫完整時段，因為不知道休息發生在哪個時間點。
- 停用的記錄畫成淡色。起訖不是數字時不畫。

## 練功計畫

功能行為見 [features/plan.md](features/plan.md)，資料格式見 [format.md](format.md#plan練功計畫)。
**計畫值是依輸入條件估算的目標，不是實際獲得的經驗**；所有數字都即時算，不存。

### 所需經驗

- `R(L)` = `levelInfo(L)` 那一列的 `required`，要是**有限的正數**才算有；沒有那一列、是 0、負數、`NaN` 都算「缺」。
- 起點 `(a, pa)`、目標 `(b, pb)`。必要的 `R`：`a`～`b−1` 每一級，以及 `b`（**只有 `pb > 0` 時**才需要）。有任何一個缺就不產生計畫，訊息指名缺哪一級（缺很多級時列前 3 個再加「…共 N 級」）。
- 總經驗 `total`：
  - `a < b`：`Σ_{L=a}^{b−1} R(L) − pa/100 × R(a) + pb/100 × R(b)`（`pb = 0` 時最後一項是 0，不查 `R(b)`）。
  - `a = b`（要求 `pb > pa`）：`(pb − pa)/100 × R(a)`。
  - `total` 必須 > 0。

### 展開時段與分配

1. 從 `start` 到 `end`（含）逐日，**星期**用跟 `weekday()` 相同的 UTC 算法（避免時區），對 `weekly` 的每一組：星期有勾就產生一個時段 `{date, start, end, hours = end − start}`。
2. 依日期、再依開始時間排序。時段鍵 `key = date + "|" + String(start) + "|" + String(end)`，同一個鍵不重複。
3. `totalHours = Σ hours`；`totalHours = 0` 不產生計畫；時段總數 > 1000 不產生計畫。
4. **需要時速** `needRate = total / totalHours`（exp/h）。
5. 第 `i` 個時段：`plannedExp = needRate × hours`；累計經驗 `cum_i = needRate × (前 i 個時段的 hours 加總)`。**最後一個時段的累計直接取 `total`**，位置直接取目標，避免浮點誤差讓最後一列差一點點。

### 位置 `pos(E)`（`0 ≤ E ≤ total` 的累計經驗 → 等級與 %）

```
rem   = pa/100 × R(a) + E
level = a
while level < b 且 rem ≥ R(level) × (1 − 1e-6):  rem −= R(level); level += 1
pct   = (level = b 且 R(b) 缺) ? 0 : min(max(rem / R(level) × 100, 0), 99.9999)
```

- **逐級的計算一律走等級表**（`planLevelMap()`），不從 `a` 掃到 `b`：總經驗只加等級表裡落在 `[a, b−1]` 的列（缺級已先擋掉），`pos()` 的迴圈上限是「等級表列數 ＋ 1」，所以 `1 → 1e15` 這種輸入立刻回報缺級、不會卡住。
- **容許誤差用相對值**（`R(level)` 的百萬分之一，約 0.0001% 的一級）：升級經驗可以大到 1e10 以上，絕對值的誤差在那種大小下會失效（double 的間距比誤差還大）。`rem` 進位後可能是 −1e-7 這種微小負數，所以 `pct` 要夾在 0 以上；上限夾在 99.9999，免得顯示成 `100.0000%`（顯示是 4 位小數，見格式化）。
- `level` 不會超過 `b`；到達 `(b, pb)` 時 `level = b`。
- 時段的「目標位置」是 `pos(cum_i)`；「本時段起點」是 `pos(cum_{i−1})`（第一個時段是 `(a, pa)`）。起點與終點等級不同時，這個時段「升級」。
- 本時段目標 %：同級時 `pct_i − pct_{i−1}`；跨級時不給 %，只給經驗與「升到 Lv X」（跟「跨級的 % 不相加」同一原則，見每日進度頁）。

### 可行性（只在 `rate` 是有限正數時）

- 預估產出 `rate × totalHours`；達成度 `= 預估產出 / total`。「預估產出 ≥ 總經驗」與下面的達成日**用同一個比較**：`x ≥ total × (1 − 1e-9)`，兩處不會不一致。
- **預估達成日**：第一個使 `rate × (累計 hours) ≥ total × (1 − 1e-9)` 的時段的日期。計畫期間內找不到時，用同一組 `weekly` 從 `end` 次日往後再展開，最多找到 `start` 之後 3660 天；仍找不到就是「—」。
  - 達成日比 `end` 早的天數 `= end − 達成日`（用日期差，不是時段數）。
- 要準時達成的時速提高比例 `= needRate / rate − 1`。

### 歷史時速 `planHistRate(workerId)`

- 取**啟用**的記錄（`isOn`）；`workerId` 是空字串時不限人員，否則 `s.workerId === workerId`。
- 只計算 `derive(s).required` 是有限正數、而且 `billHours > 0` 的記錄。**等級表沒有經驗的記錄不能算進時數**，否則它的時數被算進去、經驗卻是 0，時速會被低估。
- `歷史時速 = Σ units / Σ billHours`（分母是**計費時數**，不是時段長度）；筆數 `N`＝被計入的記錄數，`M`＝Σ billHours。
- `N = 0`、或 Σ units ≤ 0 時是「無資料」。
- **跟「人員效率」表的每小時經驗不同**：那張表把等級表沒有經驗的記錄的時數也算進分母（它們的經驗是 0）；這裡排除它們，因為計畫要的是「有根據的時速」。兩個數字可能不一樣，計畫頁的歷史欄位旁有小字說明。

### 進度

時段狀態依本機現在時刻，見 [features/plan.md](features/plan.md#時段狀態用本機時間)。

- `doneExp` = 標記為 `done` 的時段的 `plannedExp` 加總；**計畫經驗完成度** `= doneExp / total`。
- `shouldExp` = 已結束（狀態為「已結束」）的時段的 `plannedExp` 加總；**應有進度** `= shouldExp / total`。
- **落後**：已結束但標記不是 `done` 的時段數 > 0 時為落後（待填與沒練都算）；落後的經驗 `= shouldExp − doneExp`。用「時段數」判斷、不用經驗差去比大小：每個時段的 `plannedExp` 都 > 0，兩者等價，但前者不怕浮點誤差。
- **標記照存的值計算，不看時段狀態**：還沒結束的時段上若有標記（匯入的資料、系統時間被調回去），`done` 的照樣計入 `doneExp`；`shouldExp` 仍然只算已結束的時段。
- **補救時速** `= max(0, total − doneExp) / remainingHours`，`remainingHours` 是狀態為「未開始」或「進行中」的時段的 hours 加總；`remainingHours = 0` 時沒有補救時速（計畫期間已結束）。
- 這裡的 `plannedExp` 是計畫值，**不是實際獲得**；實際進度看經驗條與每日進度頁。

## 格式化

| 函式 | 用途 |
|---|---|
| `fin(n)` | 轉成有限數字，失敗時是 0，不會拋出例外 |
| `fmt0` | 整數，千分位，例如 `1,652` |
| `fmt1` | 1 位小數，用於時數 |
| `fmt2` | 2 位小數，用於天數說明 |
| `fmt4` | 4 位小數，**所有百分比一律 4 位** |
| `hhmm(v)` | 小時轉顯示：`10.5` → `10:30`，`10` → `10` |
| `weekday(d)` | 日期先經過 `normDate`，不存在的日期回傳空字串；用 UTC 計算星期，不受時區影響 |
| `normDate(v)` | `YYYY-M-D` 補零成 `YYYY-MM-DD`，並確認日期真的存在（`2026-02-30` 回傳 `null`） |
