# 技術債與已知限制

這份文件記錄目前**還沒處理、或無法在開發機上驗證**的問題，方便之後回來處理。
每一項寫明現況、影響、建議做法，以及怎麼驗證。

處理掉一項就從這裡刪掉，並在 commit 訊息裡提到它；新發現的問題也記在這裡。

最後更新：2026-09-28

---

## 一、需要其他環境才能驗證

開發機是 Windows、只有 Chrome 和 Electron，下面這些都還沒實測過。

### 1. Firefox、Safari 的版面

- **現況**：版面只在 Chrome／Electron（Chromium）驗證過。下面這些寫法，在其他瀏覽器可能表現不同。
- **要看的地方**：
  - 記錄、人員、等級三張表需要左右捲時，最右邊的改／刪會固定在右側（`position:sticky` 加 `border-collapse`）。
    舊版 Firefox／Safari 的固定格，框線可能不跟著移動。分隔線已經改用 `box-shadow`，應該能避開大部分問題。
  - 圖例色塊的位移用 `1lh`：Firefox 120、Safari 16.4 才支援，舊版會退回寫死的 `4.8px`。
  - 長文字折行用 `overflow-wrap:anywhere`：Safari 15.4 才支援，舊版會退回 `word-break:break-word`。
  - 表格的細捲軸：Firefox 用 `scrollbar-width`／`scrollbar-color`，Safari 用 `::-webkit-scrollbar`。
- **影響**：只有外觀，資料不會出錯。
- **驗證方式**：
  1. 用 Firefox、Safari（macOS／iOS）打開 https://rabbit99.github.io/grind-log/ 。
  2. 在 375、1000、1280 寬各看一次記錄頁，左右捲動記錄表，確認改／刪固定在右側、框線正常。

### 2. macOS 版 Electron

- **現況**：選單的「開啟…」（Cmd+O）、「另存新檔…」（Cmd+S）只在 Windows 版測過。
- **要看的地方**：
  - macOS 的存檔、開檔對話框是附在視窗上的 sheet，不會擋住選單列。程式有 `nativeBusy` 防止同時開兩個，但沒在 macOS 實測過。
  - 讀不出原本資料時，選單開檔會先跳確認框。這個確認框開著時如果又按 Cmd+O，按「取消」後應該會接著再問一次。
    這是推測，屬於可以接受的行為，但沒實測過。
  - 用 Cmd+W 關掉視窗後，app 還在執行；這時點選單，已經改成不動作（`win.isDestroyed()` 檢查），但沒實測過。
- **影響**：推測最多是多跳一次確認框，不會改壞資料。
- **驗證方式**：在 macOS 上 `npm install` 後 `npm start`，逐項操作上面的情境。

### 3. 螢幕閱讀器

- **現況**：兩個提示區域都用了 `role="alert"`，但沒有用 NVDA、JAWS、VoiceOver 實際聽過：
  - 讀不出資料時的紅框提示（`#loadBanner`）。
  - 等級表的提示（`#lvMsg`）。
- **可能的問題**：
  - 元素從 `hidden` 變成顯示時，VoiceOver 不一定會唸。
  - 同一則提示重複出現時，可能不會再唸一次。
  - 其他訊息區完全沒有設定 live region，出現新訊息時不會被唸出來：
    - 檔案區的 `#ioMsg`：匯入結果、「寫不進這台電腦」、「存檔失敗／開檔失敗」都寫在這裡。
    - 表單的 `#formMsg`。
    - 頁首的存檔狀態 `#saveState`。
- **建議做法**：
  - 提示有問題時，讓提示元素一直留在無障礙樹裡（空白時用 CSS 收起邊距），或者先清空文字，下一格畫面再填入。
  - 一般訊息區加上 `role="status"`（`aria-live="polite"`），紅字錯誤用 `role="alert"`。

## 二、已知限制（評估後暫不處理）

### 4. CSV 的公式防護擋不住「另存再開」

- **現況**：匯出 CSV 時，以 `= + - @`（含全形）、Tab、換行開頭的文字，前面會加 `'`，讓試算表當成純文字。
- **限制**：
  - 在 Excel 開啟後「另存成 CSV」再開啟，`'` 可能被拿掉，公式又會生效（OWASP 有提到這個已知限制）。
  - 用分號當清單分隔字元的語系（部分歐洲語系的 Excel）開啟時，是照分號切欄。這種情況下，含分號的格子雖然有加引號，還是要看 Excel 的處理方式。
- **影響**：需要使用者自己把含惡意內容的資料匯入，再經過另存，實際風險低。
- **可能的做法**：改成在引號裡加 Tab 前綴（OWASP 的替代做法），代價是 Tab 會留在資料裡。

### 5. 瀏覽器擋掉確認框時，按了沒有反應

- **現況**：下面這些動作都用 `confirm()` 確認：
  - 刪除記錄、人員、等級。
  - 還原示範資料、清空全部。
  - 讀不出原本資料時的「匯入 JSON」和 Electron 開檔。
- **限制**：Firefox 在連續跳框時，會出現「不要再讓這個網站顯示對話框」的選項。勾了之後 `confirm()` 直接回傳 false，上面這些動作按了都沒有任何反應，也沒有提示。
- **可能的做法**：改用頁面內自己做的確認框，不依賴瀏覽器的 `confirm()`。這個改動比較大，要另開分支。

### 6. 同時開兩個分頁

- **現況**：程式沒有監聽 `storage` 事件。兩個分頁同時開著時，後存檔的那個會蓋掉先存檔的內容，另一個分頁的畫面也不會更新。
- **影響**：在兩個分頁都有修改時，會掉資料。只開一個分頁的使用方式不受影響。
- **可能的做法**：
  - 監聽 `storage` 事件，另一個分頁存檔時提示「資料已在別的分頁更新」，並提供重新載入。
  - 或者用 `BroadcastChannel`，只讓最後開的分頁可以編輯。

### 7. 下載的原始內容可能有一個字元不同

- **現況**：讀不出資料時，「下載原始內容」會用 UTF-8 把原文存成檔案。
- **限制**：如果原文剛好在 emoji 中間被截斷（出現落單的 surrogate），那個字元會變成 `U+FFFD`。
- **影響**：最多影響截斷處的一個字元，其他內容完全一致。

### 8. 讀不出來的原文備份沒有清除的方法

- **現況**：讀不出資料時，原文會備份到 `grind-log/v1:unreadable`。遇到不同的原文，會另存成 `:unreadable-<時間戳>`；同一份原文不會重複存。
- **限制**：
  - 畫面上沒有任何地方可以看到或刪除這些備份。
  - 換上新資料、提示收起之後，也就拿不到它們了。
  - 備份越積越多，會吃掉 localStorage 的空間，這正是「寫不進去」的原因之一。
- **可能的做法**：在「檔案」區加一個「讀不出來的舊資料備份」清單，可以下載或刪除。

### 9. 寫不進去時的暫停不會自己解除

- **現況**：
  - 讀不出原本資料、而且原文沒有另外備份時，換上的新資料如果寫不進 localStorage，會繼續暫停自動儲存（見 [features/storage-recovery.md](features/storage-recovery.md)）。
  - 這是為了保護唯一的一份原文。
- **限制**：
  - 之後就算空間變多，也不會自動恢復存檔。
  - 要再做一次匯入、還原示範資料或清空全部，而且那次寫得進去，才會恢復。
  - 網頁上也沒有清出空間的方法（見第 8 項）。
- **影響**：暫停期間的修改不會存下來。提示和狀態列都有照實說明。

### 10. GitHub Pages 上所有專案共用同一份 localStorage

- **現況**：網頁版放在 `rabbit99.github.io/grind-log/`。同一個網域底下的其他 GitHub Pages 專案，會共用同一個 origin 的 localStorage 空間，瀏覽器通常給每個 origin 約 5MB。
- **影響**：
  - 其他專案存的東西也會佔空間。
  - 其他專案理論上也讀得到這裡的資料，只是資料本身不含機密。
- **可能的做法**：改用自訂網域，或把資料改存 IndexedDB（一樣是同 origin，但空間上限較大）。

### 11. package.json 帶了程式用不到的套件

- **現況**：`dependencies` 裡有 `jsdom` 和 `puppeteer`，程式本身沒有用到。
- **影響**：`npm install` 時，會多下載 puppeteer 附帶的瀏覽器（數百 MB）。
- **另外**：`electron` 寫的是 `^32.0.0`，開發機上測試用的是全域安裝的 35 版。
- **可能的做法**：確認沒有其他腳本在用之後，從 `dependencies` 移除這兩個套件。

## 三、待修的小問題

### 12. 表單的預設日期和下載檔名用的是 UTC 日期

- **現況**：
  - 「記一筆時段」的日期預設值是 `new Date().toISOString().slice(0,10)`。
  - 匯出 JSON、CSV、原始內容的檔名日期（`stamp()`）也是這樣算的。
  - Electron 存檔對話框的預設檔名（`main.js` 的 `file:save`）也一樣。
  - 這些都是 **UTC** 的日期，不是本地日期。
- **影響**：在台灣（UTC+8），早上 8 點前開啟頁面時：
  - 日期預設成前一天，沒注意就會登錄到錯的日期。
  - 匯出的檔名也是前一天。
- **建議做法**：改用本地日期，例如用 `getFullYear()`、`getMonth()`、`getDate()` 組成 `YYYY-MM-DD`。
- **驗證方式**：把系統時間調到早上 8 點前，重新整理頁面，確認表單日期和匯出檔名是當天。

### 13. 頁面底部的公式說明寫「÷ 時數」

- **現況**：練功記錄頁最下方的說明寫「每小時經驗 = 獲得% ÷ 100 × 該等級升級經驗 ÷ 時數」。
- **實際**：分母是**計費時數**，見 [calculations.md](calculations.md)。只有計費時數跟時段相同時，兩者才一樣。
- **建議做法**：把說明改成「÷ 計費時數（沒填就是時段長度）」。

### 14. `hhmm()` 可能顯示成 `10:60`

- **現況**：`hhmm(v)` 把小時轉成「時:分」時，分鐘是 `Math.round((v - 小時) × 60)`。
- **影響**：像 `10.9999` 這種值會顯示成 `10:60`，而不是 `11`。只有手改或匯入的資料會出現這種值，表單填的通常是整數或 .5。
- **建議做法**：先把整個值換算成分鐘再四捨五入，再拆回時和分。

### 15. 起迄時間沒有驗證範圍

- **現況**：表單的起、迄輸入框設了 `min="0" max="24"`，但 `validate()` 沒有檢查範圍。
- **影響**：例如迄填 25 照樣存進去，時數算成 `25 - 起`。時間軸會把超過 24 的部分截掉，數字卻照算。
- **建議做法**：驗證時要求 0 ≤ 起、迄 ≤ 24，並給出明確的提示。要注意舊資料可能已經有超出範圍的值，**載入時不能刪**。

### 16.（推測）打包成 exe 後可能開不了「資料格式說明」

- **現況**：Electron 選單「說明 → 資料格式說明」用 `shell.openPath` 開啟 `docs/format.md`。
- **推測**：用 electron-builder 打包後，檔案會被包進 asar 封存檔，外部程式大概開不起來。舊的 `FORMAT.md` 也一樣，不是這次移動資料夾造成的。
- **驗證方式**：實際打包一次，點選單試試看。
- **可能的做法**：把 `docs/format.md` 設成 asar 不封存（`asarUnpack`），或改成在 app 內的視窗顯示。

### 17. 讀入整理和計算認得的數字不一致

- **現況**：
  - 讀入時的 `numField()` 只把十進位寫法轉成數字，`"0x33"`、`"0b101"`、`"1e999"` 這類寫法保留原字串，並算成「認不得」。
  - 計算和顯示用的是 `Number()`／`fin()`，會把 `"0x33"` 當成 51、`"0b101"` 當成 5。
- **影響**：
  - 匯入訊息說「無法辨識（保留原樣，計算時不採用）」，但這類值其實有被採用：
    - 等級 `"0x33"` 會對到 Lv 51。
    - 獲得% `"0x33"` 會顯示 `51.0000`、算成 51%。
  - 只有手改或來源奇怪的檔案才會出現。
- **建議做法**：計算端也改用只認十進位的規則，例如 `pctOf`、`levelInfo`、`fin` 對字串先用跟 `numField` 相同的正規表示式判斷。要注意這會改變這類舊資料的計算結果，要先確認使用者手上的資料有沒有這種值。

## 四、Google 試算表同步的已知限制

### 18. 讀取檢查和寫入之間的空檔

- **現況**：上傳前會先讀雲端、確認沒有被別台改過，再寫入。對話框選完之後也會再讀一次，雲端又變了就重新問。但最後一次讀取和寫入之間仍有一小段空檔（通常不到一秒）。
- **影響**：如果另一台裝置剛好在這個空檔內寫入，它的修改會被這次上傳蓋掉，不會跳出衝突對話框。機率很低，被蓋掉的內容可以從試算表的「版本記錄」找回。
- **可能的做法**：用 Drive 的 `If-Match`／revision 條件寫入，但 Sheets API 的 batchUpdate 不支援條件寫入，需要換成其他寫法。

### 19. 在試算表裡輸入 `10:30`、`5%`

- **現況**：在試算表裡手動輸入時，試算表會自動轉換：
  - 起迄輸入 `10:30`，會存成一天的比例（0.4375），讀回來被當成 0.4375 點。
  - 獲得% 輸入 `5%`，會存成 0.05，讀回來被當成 0.05%。
- **影響**：只有在試算表裡手動修改、而且用這種寫法時才會發生。README 和規格已經註明起迄要填小時數字（10.5）、獲得% 直接填數字（5）。
- **可能的做法**：讀取時改用 `FORMATTED_VALUE` 取得顯示文字，再解析 `時:分`、`%` 格式。

### 20. 開啟頁面和權杖過期時都要點一下

- **現況**：純前端的 token model 沒有長期權杖，開啟頁面後要按一次「同步」，約 1 小時後再按一次。
- **可能的做法**：要完全免點擊，需要一個小後端（例如 Cloudflare Workers）用授權碼流程保存 refresh token，這會牽涉到保管使用者的權杖。

### 21. Electron 版不支援同步

- **現況**：Google 登入元件只能在 http(s) 網址下運作，Electron 是用 `file://` 載入，所以同步區塊不顯示。
- **可能的做法**：在 Electron 主程序用系統瀏覽器加上 loopback 的 OAuth 流程（PKCE）取得權杖，再交給網頁端使用。

### 22. 對話框需要較新的瀏覽器

- **現況**：衝突時的選擇用 `<dialog>` 的 `showModal()`，需要 Safari 15.4、Chrome 37、Firefox 98 以上。
- **影響**：更舊的瀏覽器遇到衝突時會顯示「同步失敗」，不會覆蓋任何資料。對話框沒開啟時用 CSS 隱藏（`dialog.cloudask:not([open])`），舊瀏覽器不會把按鈕顯示在頁面底部。

### 23. 兩台裝置同時第一次連結

- **現況**：雲端還沒有試算表時，第一次連結會建立一份。兩台裝置如果在同一瞬間（建立完成前）都按「連結 Google 帳號」，會各自建立一份，之後各自同步到不同的試算表，看不到對方的修改。
- **影響**：機率很低，要兩台幾乎同時按。發生時在其中一台「中斷連結」再重新連結即可：連結時會找最近修改的那一份。
- **可能的做法**：建立並寫入後再查一次，發現有別的試算表時提示使用者選一份，並把另一份移到垃圾桶。
