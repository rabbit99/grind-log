# 檔案：匯出、匯入、還原示範資料、清空全部

## 目的

備份、還原、搬移資料，以及接回試算表。

## 介面

「練功記錄」頁左欄的「檔案」面板：

- 「匯出 JSON」`#btnExport`、「匯出 CSV」`#btnCsv`、「匯入 JSON」`#btnImport`（搭配隱藏的 `#fileInput`）。
- 「開啟檔案」`#btnOpenFile`、「儲存到檔案」`#btnSaveFile`：只有 Electron 版才顯示（`#nativeRow`）。
- 「還原示範資料」`#btnDemo`、「清空全部」`#btnReset`。
- 訊息 `#ioMsg`。

## 行為規則

### 匯出 JSON

- 下載 `grind-log-YYYY-MM-DD.json`，內容是目前的整份資料（縮排 2 格），並更新 `meta.updatedAt`。
- 讀不出原本資料的期間，匯出的是**畫面上的資料**，不是讀不出來的原文。訊息會用紅字說明，並指引改按「下載原始內容」。

### 匯出 CSV

- 下載 `grind-log-YYYY-MM-DD.csv`：UTF-8 加 BOM（Excel 開啟不會亂碼），換行是 LF。
- 每一列是一筆記錄，依日期、開始時間排序，**包含停用的記錄**（「啟用」欄是／否）。
- 欄位：
  - 日期、星期、起、迄、時數、計費時數。
  - 人員、等級、獲得%、該級升級經驗、獲得經驗。
  - 每小時經驗、每小時%（4 位小數）、費用、每百萬經驗成本。
  - 備註、啟用。
- **每一格都經過 `csvCell()`**：
  - 文字以 `=` `+` `-` `@`（含全形 `＝＋－＠`）、Tab、換行開頭時，前面加 `'`，讓試算表當成純文字，防止公式注入。
  - 數字（包括 `-1.5` 這種負數、`"-0.0833"` 這種數字字串）照原樣輸出。
  - 含逗號、引號、換行、分號、Tab 的格子用引號包起來。
  - 人員名稱和備註一律加引號。

### 匯入 JSON

1. 按「匯入 JSON」開啟選檔視窗。
2. 讀不出原本資料的期間，**選好檔案之後**才跳確認框。
   - 不能在選檔之前問：確認框停太久，瀏覽器會擋掉選檔視窗。
3. `normalize(資料, issues)` 整理格式，規則見 [format.md](../format.md#讀入時的整理)。
   - 整理後沒有任何記錄也沒有任何等級時，視為「看起來不是 grind-log 檔案」。
4. `applyLoaded()`：先在畫面上試畫一次，成功才寫進 localStorage；中途出錯就退回原本的資料，顯示「讀不了這個檔案：…」。
5. 訊息：「已匯入 N 筆記錄」。
   - 有整理項目時，列出「自動整理：…」。
   - 只有補零、自動編號這類無害的整理時是綠字；有東西被拿掉或認不得時是紅字。
6. **匯入是整份取代**，不是合併。

### 還原示範資料

- 確認後換成 `seed()` 的示範資料：8 筆記錄、「我」和「代練」兩位人員、Lv 41～54 的等級表。
- 用途：回到剛打開網頁時的範例狀態。

### 清空全部

確認後全部歸零：記錄、人員、等級表都清空。標題回到「練功記錄」。

### 換資料之後

匯入、Electron 開檔、還原示範、清空之後，都會：

- 回到第 1 頁；表單回到新增模式；清掉等級表的提示。
- 呼叫 `resumeSaving()` 恢復自動儲存，見 [storage-recovery.md](storage-recovery.md)。
- 寫不進 localStorage 時，訊息用紅字補充原因：
  - 匯入、開檔的資料：「請先用「匯出 JSON」另存一份」。
  - 還原示範、清空：「之後的修改不會自動儲存」。

### 確認框的內容

- 還原示範資料、清空全部都會確認，並附上建議：
  - 平常：「建議先匯出 JSON 備份」。
  - 讀不出原本資料時：提醒先按「下載原始內容」。
- 平常的匯入不確認，只有讀不出原本資料時才確認。

### Electron：開啟檔案、儲存到檔案

- 走主程序的系統對話框，見 [architecture.md](../architecture.md#electron)。
- 開檔的後續流程跟匯入 JSON 大致相同：整理、試畫、寫入、訊息。有幾處不同：
  - 讀不出原本資料時的確認框，在開檔對話框**之前**就跳出來。瀏覽器的匯入是選好檔案之後才確認，因為瀏覽器開選檔視窗必須在使用者點擊後不久；Electron 的開檔對話框由主程序開啟，推測不受這個限制。
  - 格式錯誤時的訊息是「檔案格式不對：…」，匯入 JSON 是「讀不了這個檔案：…」。
  - 成功訊息是「已開啟 <路徑>」。
- 存檔的內容跟匯出 JSON 相同。讀不出原本資料時，同樣用紅字說明存的是畫面上的資料。
- 選單的「開啟…」（Ctrl+O）、「另存新檔…」（Ctrl+S）走同一段程式。觸發前會先讓正在編輯的輸入框離開焦點，否則人員表、等級表剛改的那一格還沒寫進資料。
- 對話框開著時不會再開第二個（`nativeBusy`）。
- 對話框本身出錯時，顯示「存檔失敗：…」「開檔失敗：…」。

## 設計決策

- **瀏覽器版不顯示開檔／存檔按鈕**：使用者要求網頁版只用匯出／匯入 JSON。
- **匯入是原子的**：以前先存再畫，畫面一出錯就顯示「讀不了這個檔案」，資料卻已經被換掉了。
- **CSV 包含停用的記錄**：試算表那邊可以自己篩選。

## 相關程式

`#btnExport`、`#btnCsv`、`#fileInput` 的事件；`csvCell()`、`download()`、`stamp()`、`normalize()`、`applyLoaded()`、`resumeSaving()`、`backupAdvice()`、`confirmReplaceUnreadable()`；Electron 區塊 `if(window.grindLogNative){…}`；`main.js` 的 `file:save`、`file:open`。

## 修改時要檢查

- 真實資料匯出的 CSV 和修改前逐字相同（除非這次就是要改 CSV）。
- 匯入格式錯誤、內容怪異的檔案，以及畫面試畫失敗時，原本的資料都不會被換掉。
- Electron 版用 `electron` 實際跑一次，測試方法見 [development.md](../development.md)。
