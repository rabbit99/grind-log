# 等級經驗對照表

## 目的

登錄每一級「升到下一級所需的經驗」。記錄的獲得% 靠它換算成經驗值，才能跨等級比較效率。

## 介面

「練功記錄」頁右欄最下方的摺疊面板「等級經驗對照表」`#tblLevels`：

- 每一列：等級、升下一等經驗、可信度（實測／推估）、備註、「刪」。
- 「新增等級」按鈕 `#btnAddLevel`。
- 下方的紅字提示 `#lvMsg`：沒有訊息時隱藏，不佔版面。

## 行為規則

### 識別方式

每一列用它在 `db.levels` 裡的**位置**識別（`data-li`、`data-delli`），不是用等級數字。

### 排序

- 依 `Number(level)` 由小到大排列，跟記錄查經驗用的是同一種比對：
  - 等級空白（`null`、`""`）當成 0，排在最前面。
  - `"0x33"` 當成 51，排在 51 的位置。
  - `Number()` 之後不是有限數字的（例如 `"5%"`）排在最後。
- 同一級有好幾列時，照原本的先後排列。**上面那列就是記錄在用的那列**，因為 `levelInfo` 取第一列符合的。

### 修改

- 改完離開輸入框才生效。升級經驗用 `parseFloat`，不是數字時存成 0。
- **改等級數字時會先檢查**，有問題就擋下來、輸入框改回原值，並在 `#lvMsg` 說明原因：
  - 空白或不是數字：「等級要填數字」。
  - 和別列重複：「等級表已經有 Lv X，不能重複」。
  - 撞到等級空白或認不得、但計算時也算同一級的列：「等級表有一列「…」計算時也算 Lv X，請先修改那一列」。
    - 等級空白會被當成 0，`"0x33"` 會被當成 51。
- 提示會留到下次編輯等級表，或換掉整份資料時才清掉。
  - 重畫時不清，否則「改完等級直接點新增等級」時，同一次點擊造成的重畫會立刻把提示蓋掉。

### 刪除

- **只刪那一列**。先跳確認框，第一行是「刪除「Lv X」這一列？」；等級空白時稱為「等級空白的那列」。
- 還有其他列也算同一級時，加上「只會刪掉這一列」。
- 「記錄正在用這列」指的是：有記錄是這個等級，而且這列是 `levelInfo` 找到的第一列。刪掉後接手的是剩下同級的第一列。依情況再加一句：

  | 記錄正在用這列 | 這列有升級經驗 | 接手的列有升級經驗 | 加上的說明 |
  |---|---|---|---|
  | 是 | 是 | 是 | 「記錄會改用剩下那列的升級經驗」 |
  | 是 | 是 | 否，或沒有接手的列 | 「有 N 筆記錄用到這個等級的經驗，刪除後會算不出它們的經驗和時速」 |
  | 是 | 否 | 是 | 「這列沒有升級經驗，刪除後記錄會改用剩下那列的升級經驗」 |

  其他情況不加說明。**這列本身沒有升級經驗時，不能說「會算不出」**，因為本來就算不出。

### 新增

- 新增「目前最大的有效等級 + 1」，升級經驗 0，可信度「推估」。
- 算出來的新等級已經存在時（等級值大到 +1 沒有變化），不新增，並提示直接修改表格。

### 可信度

標成「推估」的等級，在記錄表和每日進度頁會顯示紅色「推」字。之後取得實測值直接覆蓋，所有記錄的經驗數字會一起重算。

## 邊界情況

- **認不得的等級**（`"0x3C"`）：`number` 輸入框顯示不了，所以用 placeholder 顯示原文，提示裡指名的列才找得到。
- **舊資料裡已經有重複等級**：每一列都能各自修改、刪除，可以修正回來。
- **等級空白的列**：可以修改和刪除。計算時會被當成 Lv 0。

## 設計決策

- **用位置而不是等級數字識別**：以前用等級數字找列，舊資料有重複等級時，改第二列會改到第一列，刪除會兩列一起刪；等級空白的列完全不能改或刪。
- **不能在介面上做出重複等級**：記錄查經驗只看第一列，重複會讓「改了卻沒效果」。
- **匯入時略過重複、無效的等級，載入時不刪**：見 [format.md](../format.md#讀入時的整理)。

## 相關程式

`renderLevels()`、`lvMsg()`、`lvLabel()`、`levelInfo()`；`#tblLevels` 的 change、click 事件；`#btnAddLevel`。

## 修改時要檢查

- 舊資料有重複等級（例如兩列 48）：改第二列、刪第二列都只影響那一列。
- 刪掉記錄正在用的列，剩下那列有經驗和沒經驗兩種情況：確認框的說明和實際的經驗變化是否一致。
- 改完等級不離開輸入框、直接點「新增等級」：被擋下的提示要留著。
