# 可選模組：計費與成本

## 目的

對一般玩家來說，「人員時薪、計費時數、費用、每百萬經驗成本」是用不到的複雜度，第一眼看到反而困惑。這個功能把它們收成**進階模組，預設關閉**；需要的人在「人員與時薪」面板勾選開啟。

關閉只是**隱藏顯示**：資料、計算、匯出、Google 同步都完全不變。

## 介面

- 開關 `#costToggle`（checkbox）：在「練功記錄」頁右欄「人員與時薪」`details.tool` 面板的最上方，文字是「啟用「計費與成本」（進階）：記錄人員時薪與計費時數，計算費用與每百萬經驗成本」。
- 說明小字 `#costNote`：目前是「自動開啟（資料中有計費人員或計費時數）」、「預設關閉」，或使用者按過開關之後的「依你的設定」。
- 關閉時被隱藏的東西（都帶共用 class `c-cost`，由 `body.cost-off .c-cost{display:none!important}` 隱藏）：
  1. 經驗條統計的「本級花費」「累計花費」（[hero.md](hero.md)）。
  2. 人員效率表的「費用」「每百萬經驗成本」兩欄（含合計列），以及標題旁那句價格提示（[worker-stats.md](worker-stats.md)）。
  3. 記錄表的「計費」「費用」兩欄（[records.md](records.md)）。
  4. 記錄表單的「計費時數」欄 `#f-bh`（[session-form.md](session-form.md)）。
  5. 「人員與時薪」編輯表的「時薪」「計費」兩欄（[workers.md](workers.md)）。
  6. 每日進度頁的「花費」「計費時數」：表格的欄，以及 900px 以下卡片裡對應的那幾列（[daily.md](daily.md)）。
- **不受影響**：等級、獲得%、每小時經驗、每小時%、人員選單、人員效率表的其他欄、練功計畫頁。

## 行為規則

### 有效狀態

UI 偏好 `grind-log/v1:ui` 的 `cost` 欄位只認 `"on"`／`"off"`，缺少或其他值都是「未設定」。

```
costOn() = cost 是 "on"  → 開
         = cost 是 "off" → 關
         = 未設定        → costAuto()
costAuto() = 任一人員 billable === true 或 fin(hourlyRate) > 0，
             或任一記錄的 billableHours 不是 null  → 開；否則關
```

- **每次 `render()` 開頭重新判斷**（`applyCost()`）：匯入、開檔、雲端下載把資料換掉時，沒有明確偏好的人會自動跟著資料開關；有明確偏好的人不受資料影響。
- **既有使用者**（資料含計費人員或計費時數）自動開啟，畫面與以前相同。
- 使用者按過開關後存成明確的 `"on"`／`"off"`，之後不再自動判斷。

### 關閉時的細節

- **`#f-bh` 一律不顯示**（`syncBhField()` 先看 `costOn()`）。**修改既有記錄時要保留它原本的計費時數**：`readForm()` 在模組關閉時直接沿用那筆的 `billableHours`，不會因為欄位看不到而清成空值；新增記錄則是 `null`。驗證「計費時數不能是負的」也只在開啟時做（關閉時使用者看不到那個欄位，不該被擋）。
- **新增人員**：模組關閉時 `billable: false`、時薪 0，不會因為新增人員而讓自動判斷變成「開」；開啟時維持以前的預設（`billable: true`、時薪 0）。
- **刪除人員的確認框**：模組關閉時不提「費用也會變成 0」。
- 經驗條「本級投入」的滑過說明，關閉時寫「時數」而不是「計費時數」。
- 切換開關只寫 UI 偏好，**不碰 `db`、不更新 `meta.updatedAt`、不標記雲端 dirty**。

## 邊界情況

- **資料有計費設定、但使用者明確關閉**：欄位看不到也改不到，但資料還在；匯出 JSON／CSV、Google 試算表仍包含完整的計費資料與費用欄。要看或改就把開關打開。
- **關閉時第一次開啟的示範資料**：沒有計費人員，模組自動關閉；使用者新增人員後仍是關閉（新人員預設不計費）。
- **`db.workers`／`db.sessions` 壞掉**（不是陣列、含非物件）：`costAuto()` 內部防禦，不拋例外，視為沒有計費。
- **人員時薪是數字文字**（`"150"`）：載入時轉成數字，會被判為計費。

## 設計決策

- **只隱藏、不改資料**：董事長要求不改資料格式；隱藏用 CSS class，計算與匯出完全不變，所以可以隨時切換、不會丟資料。
- **自動判斷**：既有使用者（含計費資料）不必做任何事，畫面跟以前逐元素相同；新使用者的示範資料不含計費，看到的是乾淨的版本。
- **預設關閉**：公開給一般玩家時，第一眼不該出現時薪與費用。
- **開關放在「人員與時薪」面板**：那裡本來就是設定時薪與計費的地方，要用的人自然會找到。
- **`display:none` 而不是 `visibility`／`hidden` 屬性**：欄位要整個消失（不佔寬度），螢幕閱讀器也不會讀到。欄位變少只會讓表格更寬鬆，記錄表固定欄（`.act`）、`is-scroll`、`has-note`、每日進度頁的最小寬度判斷都照舊運作。

## 相關程式

`costPref`（UI 狀態）、`costAuto()`、`costOn()`、`applyCost()`；`render()` 開頭呼叫 `applyCost()`；`#costToggle` 的 change 事件；各 render 函式產生的 `c-cost` class（`renderHero()`、`renderWorkers()`、`renderSessions()`、`renderWorkerEdit()`、`dayRowHtml()`、`renderDaily()`）；`syncBhField()`、`readForm()`、`validate()`；`#btnAddWorker`、`#tblWorkerEdit` 的刪除確認。

## 修改時要檢查

- 新增任何跟費用、時薪、計費有關的欄位或文字時，記得加 `c-cost`（th 和 td、動態與靜態兩處都要）。
- 模組開啟時畫面與沒有這個模組之前逐元素相同（含 901px 以上）；關閉時各表格沒有殘留的空欄、不出現左右捲。
- 用「含計費人員的舊資料」確認自動開啟；用示範資料確認自動關閉；切換後重新整理仍記得。
- 關閉狀態下修改一筆有計費時數的記錄，儲存後計費時數還在。
- 匯出 JSON／CSV、toSheets 在開啟與關閉時逐位相同。
