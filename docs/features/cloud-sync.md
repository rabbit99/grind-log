# Google 試算表同步

## 目的

在手機、桌機等不同裝置之間使用同一份存檔，不必手動搬 JSON 檔。
存檔放在**使用者自己的 Google 雲端硬碟**，是一份 Google 試算表，可以直接在試算表裡查看或修改。

## 介面

「練功記錄」頁左欄「檔案」面板裡的「Google 試算表同步」區塊 `#cloudBox`：

- 「連結 Google 帳號」／「同步」按鈕 `#btnCloudSync`。
- 「開啟試算表」連結 `#lnkCloudSheet`：連結後才顯示。
- 「中斷連結」`#btnCloudUnlink`：連結後才顯示。
- 狀態訊息 `#cloudMsg`：成功的訊息後面附上時間。
- 「下載這台的舊資料備份」`#btnCloudBackup`：「用雲端的」取代這台之前另存的備份，有備份時才顯示。下載後可以用「匯入 JSON」還原。
- 需要使用者決定時的對話框 `#cloudDialog`：「用雲端的」「用這台的」「先不要」。

以下情況整個區塊不顯示：

- 沒有設定 Google 用戶端 ID（`GOOGLE_CLIENT_ID` 是空的）。
- Electron 版，或用 `file://` 開啟：Google 登入元件只能在 http(s) 網址下使用。

## 權限與隱私

- 只要求 `https://www.googleapis.com/auth/drive.file`：**只能存取這個 App 自己建立的檔案**，看不到使用者雲端硬碟裡的其他檔案。這是 Google 的非敏感權限，不需要送審。
- 登入用 Google Identity Services 的 token model，純前端，沒有後端伺服器，資料不經過任何第三方。
- 存取權杖（access token）只放在記憶體，不寫進 localStorage；約 1 小時過期。
- Google 規定取得權杖一定要由使用者點擊觸發，所以：
  - 開啟頁面後要按一次「同步」。
  - 權杖過期後，也要再按一次。
- Google 的登入元件 `https://accounts.google.com/gsi/client` 只在第一次按按鈕時才載入，沒用這個功能的人不會載入。

## 雲端試算表的格式

試算表名稱「練功記錄（Grind Log）」，用 Drive 的 `appProperties`（`grindLog: v1`）標記，在別台裝置連結時靠它找到同一份。

四個工作表，第一列是欄位名稱，讀取時**依欄位名稱對應**，所以欄位順序可以調整：

| 工作表 | 欄位 |
|---|---|
| 記錄 | id、日期、起、迄、人員 id、等級、獲得%、計費時數、啟用、備註、其他欄位（JSON）；右邊另有「（自動計算）」欄：人員、星期、時數、獲得經驗、每小時經驗、費用 |
| 人員 | id、名稱、時薪、計費、備註、其他欄位（JSON） |
| 等級 | 等級、升下一等經驗、可信度（實測／推估）、備註、其他欄位（JSON） |
| 設定 | 兩欄「欄位、值」：schema、title、unit、currency、updatedAt、meta 其他欄位（JSON）、其他欄位（JSON） |

- **寫入**用 `RAW`：文字不會被試算表解讀成日期、百分比或公式，`"5%"`、`"=1+1"` 都照原字串存。
- **自動計算的欄位**只是方便查看，讀回來時忽略，改了也沒有作用。
- **資料格式裡沒定義的欄位**（未知欄位）放進「其他欄位（JSON）」，來回同步不會掉。
- **在試算表裡自己加的欄位**：讀取時當成那一列的其他欄位，下次上傳會收進「其他欄位（JSON）」。
- **讀取時**：
  - 在試算表裡手動輸入的日期，會被試算表存成日期序號，讀回來時轉成 `YYYY-MM-DD`；`2026/9/5` 這種寫法也會轉換。
  - 啟用、計費這兩欄，`FALSE`、`false`、`否`、`0` 都算否。
  - 讀回來的資料照「匯入」的規則整理，見 [format.md](../format.md#讀入時的整理)。有整理項目時會列在訊息裡。
- **起、迄要填小時數字**（例如 10.5）。在試算表裡輸入 `10:30`，會被存成一天的比例（0.4375），讀回來就錯了。

## 同步規則

本機的 localStorage 仍然是這台裝置的工作副本，雲端是各裝置共用的版本。
同步狀態存在 `grind-log/v1:sync`：試算表 id、上次同步時雲端內容的指紋、這台有沒有還沒上傳的修改。

### 判斷誰改過

- **雲端有沒有被改過**：
  - 讀取雲端四個工作表的內容，算出指紋。
  - 跟上次同步時記下的指紋比對，不一樣就代表被別台裝置或試算表手動改過。
  - 不用 Drive 的版本號，因為試算表的版本號更新可能延遲，容易誤判。
- **這台有沒有改過**：連結後，每次存檔成功就標記「有未上傳的修改」。

### 按「同步」或自動上傳時

| 雲端改過 | 這台改過 | 動作 |
|---|---|---|
| 否 | 否 | 什麼都不做，顯示「已是最新」 |
| 否 | 是 | 上傳這台的資料 |
| 是 | 否 | 下載雲端的資料，取代這台，不必詢問，因為這台沒有會遺失的修改 |
| 是 | 是 | **衝突**：跳出對話框，讓使用者選「用雲端的」或「用這台的」 |

### 第一次連結

- 雲端還沒有試算表：建立一份，上傳這台的資料。
- 雲端已經有了（例如在別台裝置連結過）：
  - 內容跟這台一樣：直接完成連結。
  - 不一樣：跳出對話框選擇，並顯示兩邊的記錄筆數和最後修改時間。

### 對話框的選擇

- **用雲端的**：
  1. 先把這台的資料另存到 `grind-log/v1:local-backup`，只留最新一份。可以用「下載這台的舊資料備份」取回。
     - 備份存不進去（空間不足）時，先跳確認框，建議先匯出 JSON。
  2. 再用雲端的資料取代這台。
- **用這台的**：上傳這台的資料，取代雲端。被取代的內容可以從試算表的「檔案 → 版本記錄」找回。
- **先不要**：不同步，維持原狀，之後按「同步」會再問。

### 自動上傳

- 連結後，每次修改約 2 秒後自動上傳，會先照上表判斷。
- 自動上傳不會跳出 Google 登入視窗。權杖過期時只顯示「有修改還沒同步，按「同步」上傳」。
- 開啟頁面時不會自動下載，要按一次「同步」。

### 不能破壞的保護

- **讀不出原本資料（`loadProblem`）的期間絕不上傳**：
  - 這時畫面上是空白資料，上傳會蓋掉雲端。
  - 對話框裡的「用這台的」會停用；「用雲端的」可以用來救回資料。
- **雙方都改過時不會悄悄覆蓋任何一邊**，一定要使用者選擇。
- 雲端的資料換進這台時，走跟匯入相同的 `applyLoaded()`：先試畫，成功才寫入。

### 中斷連結

- 清掉這台的同步狀態，並撤銷權杖。
- 雲端的試算表不會被刪除。之後再連結會找到同一份。
- 雲端的試算表被刪除或移到垃圾桶時，同步會顯示找不到，並提供重新建立。

## 相關程式

`index.html` 的「Google 試算表同步」區段：

- 狀態：`GOOGLE_CLIENT_ID`、`cloud`（同步狀態）、`cloudToken`。
- 登入：`cloudLoadGis()`、`cloudGetToken()`。
- API：`cloudApi()`、`cloudFind()`、`cloudCreate()`、`cloudRead()`、`cloudWrite()`。
- 格式轉換：`toSheets()`、`fromSheets()`、`sheetHash()`。
- 同步流程：`cloudSync()`、`cloudMarkDirty()`、`cloudAsk()`。
- 在 `persist()` 成功後會呼叫 `cloudMarkDirty()`。

## 設計決策

- **用試算表，不用 JSON 檔**：使用者要能直接在 Google 試算表裡看資料。
- **只要求 `drive.file`**：Sheets API 也接受這個非敏感權限，所以不需要送審，可以開放給所有人使用。
- **開放給所有人**：每個人的資料都存在自己的雲端硬碟。
- **雙方都改過時一定要問**：使用者選的規則，避免任何一邊的修改被悄悄蓋掉。
- **自動上傳**：使用者選的；開啟頁面時仍要按一次，這是 Google 的規定。
- **寫入用單一個 batchUpdate**：先清除再寫入分成兩個請求的話，中途失敗會留下空白或新舊混合的試算表。
- **用內容指紋判斷雲端有沒有改過**：試算表的 Drive 版本號可能延遲更新。

## 修改時要檢查

- 用模擬的 Google API（`tools/make-cloud-test.js`，見 [development.md](../development.md#google-試算表同步)）跑過四種情況：沒改、只有這台改、只有雲端改、雙方都改。另外還要測第一次連結、試算表被刪除、權杖過期、寫入失敗。
- `toSheets` → `fromSheets` 來回轉換後，真實資料的內容完全不變，包括未知欄位、`"5%"` 這類認不得的值、停用的記錄。
- 讀不出原本資料時，絕對不會上傳。
- 沒設定用戶端 ID、Electron 版時，整個區塊不顯示，其他功能完全不受影響。
