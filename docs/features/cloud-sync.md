# Google 試算表同步

## 目的

在手機、桌機等不同裝置之間使用同一份存檔，不必手動搬 JSON 檔。
存檔放在**使用者自己的 Google 雲端硬碟**，是一份 Google 試算表，可以直接在試算表裡查看或修改。

## 介面

「練功記錄」頁左欄「檔案」面板裡的「Google 試算表同步」區塊 `#cloudBox`：

- 標題旁的「隱私權政策」連結，開啟 `privacy.html`：Google 要求使用 OAuth 的首頁要能連到隱私權政策。
- 「連結 Google 帳號」／「同步」按鈕 `#btnCloudSync`。
- 「開啟試算表」連結 `#lnkCloudSheet`：連結後才顯示。
- 「中斷連結」`#btnCloudUnlink`：連結後才顯示。
- 狀態訊息 `#cloudMsg`：成功的訊息後面附上時間。
- 「下載這台的舊資料備份」`#btnCloudBackup`：「用雲端的」取代這台之前另存的備份，有備份時才顯示。下載後可以用「匯入 JSON」還原。
- 需要使用者決定時的對話框 `#cloudDialog`：「用雲端的」「用這台的」「先不要」。
  - 預設焦點在「先不要」，避免誤按；Esc 等於「先不要」。
  - 沒開啟時用 CSS 隱藏，不支援 `<dialog>` 的舊瀏覽器也不會把按鈕顯示在頁面上。

以下情況整個區塊不顯示：

- 沒有設定 Google 用戶端 ID（`GOOGLE_CLIENT_ID` 是空的）。目前已設定，這一條只在拿掉 ID 時才會發生。
- Electron 版，或用 `file://` 開啟：Google 登入元件只能在 http(s) 網址下使用。

## 權限與隱私

- 只要求 `https://www.googleapis.com/auth/drive.file`：**只能存取這個 App 自己建立的檔案**，看不到使用者雲端硬碟裡的其他檔案。這是 Google 的非敏感權限，不需要送審。
- 登入用 Google Identity Services 的 token model，純前端，沒有後端伺服器，資料不經過任何第三方。
- 存取權杖（access token）只放在記憶體，不寫進 localStorage；約 1 小時過期。
- Google 規定取得權杖一定要由使用者點擊觸發，所以：
  - 開啟頁面後要按一次「同步」。
  - 權杖過期後，也要再按一次。
- 登入視窗 3 分鐘沒有完成（例如被切到背景後忘了），當成失敗，按鈕恢復可以按。
- Google 的登入元件 `https://accounts.google.com/gsi/client`：
  - 還沒連結時，按下按鈕才載入，沒用這個功能的人不會載入。
  - 已經連結時，開啟頁面就先載入，按「同步」時登入視窗才不會因為等載入太久而被瀏覽器擋掉。
- LINE、Facebook 這類 App 內建的瀏覽器會擋 Google 登入，要改用 Chrome 或 Safari 開啟。

## 雲端試算表的格式

試算表名稱「練功記錄（Grind Log）」，用 Drive 的 `appProperties`（`grindLog: v1`）標記，在別台裝置連結時靠它找到同一份。

四個工作表，第一列是欄位名稱，讀取時**依欄位名稱對應**，所以欄位順序可以調整：

| 工作表 | 欄位 |
|---|---|
| 記錄 | id、日期、起、迄、人員 id、等級、獲得%、計費時數、啟用、備註、其他欄位（JSON）；右邊另有「（自動計算）」欄：人員、星期、時數、獲得經驗、每小時經驗、費用 |
| 人員 | id、名稱、時薪、計費、備註、其他欄位（JSON） |
| 等級 | 等級、升下一等經驗、可信度（實測／推估）、備註、其他欄位（JSON） |
| 設定 | 兩欄「欄位、值」：schema、title、unit、currency、updatedAt、meta 其他欄位（JSON）、其他欄位（JSON） |

- **寫入**時每一格直接指定型別（數字、文字、是否），不經過試算表的自動判斷：文字不會被解讀成日期、百分比或公式，`"5%"`、`"=1+1"` 都照原字串存。
- **自動計算的欄位**只是方便查看，讀回來時忽略，改了也沒有作用。
- **資料格式裡沒定義的欄位**（未知欄位）放進「其他欄位（JSON）」，來回同步不會掉。
- **在試算表裡自己加的欄位**：讀取時當成那一列的其他欄位，下次上傳會收進「其他欄位（JSON）」。
- **讀取時**：
  - 在試算表裡手動輸入的日期，會被試算表存成日期序號，讀回來時轉成 `YYYY-MM-DD`；`2026/9/5` 這種寫法也會轉換。
  - 啟用、計費這兩欄，`FALSE`、`false`、`否`、`0`、`no` 都算否；空白等於沒填。
  - 讀回來的資料照「匯入」的規則整理，見 [format.md](../format.md#讀入時的整理)。有整理項目時會列在訊息裡。
- **在試算表裡手動修改時**，試算表會自動轉換某些寫法，讀回來就錯了：
  - 起、迄要填小時數字（例如 10.5）。輸入 `10:30` 會被存成一天的比例（0.4375）。
  - 獲得% 直接填數字（例如 5）。輸入 `5%` 會被存成 0.05。
- **格式檢查**：讀回來的試算表少了任何一個工作表或欄位時，視為格式壞掉，**絕不拿來取代這台**。
  - 必要欄位是上表列出的**所有**欄位（「（自動計算）」欄除外），包括「其他欄位（JSON）」。
    - 只檢查幾個重要欄位不夠：例如「啟用」被改名時，讀回來會悄悄變成全部啟用；「人員 id」被改名時，所有記錄都找不到人員。接著又會自動上傳到所有裝置。
  - 「設定」工作表要有「欄位、值」兩欄，第一欄要有 schema、title、unit、currency、meta 其他欄位（JSON）、其他欄位（JSON）這幾列。
  - 整份試算表連欄位名稱都沒有時，也算壞掉。
  - 按「同步」時跳出對話框，只能選「用這台的」（重新寫入整份）或「先不要」（自己到「檔案 → 版本記錄」還原）。對話框會列出雲端還有幾筆記錄，免得以為雲端沒東西就蓋掉。
  - 自動上傳時只顯示訊息。讀不出這台的資料時也不能重新寫入，訊息只請使用者到版本記錄還原。

## 同步規則

本機的 localStorage 仍然是這台裝置的工作副本，雲端是各裝置共用的版本。
同步狀態存在 `grind-log/v1:sync`：試算表 id、上次同步時雲端內容的指紋、這台有沒有還沒上傳的修改。

### 判斷誰改過

- **雲端有沒有被改過**：
  - 讀取雲端四個工作表的內容，算出指紋。
  - 跟上次同步時記下的指紋比對，不一樣就代表被別台裝置或試算表手動改過。
  - 不用 Drive 的版本號，因為試算表的版本號更新可能延遲，容易誤判。
- **這台有沒有改過**：連結後，每次存檔成功就標記「有未上傳的修改」。

### 按「同步」或自動上傳時

| 雲端改過 | 這台改過 | 動作 |
|---|---|---|
| 否 | 否 | 什麼都不做，顯示「已是最新」 |
| 否 | 是 | 上傳這台的資料 |
| 是 | 否 | 下載雲端的資料，取代這台，不必詢問，因為這台沒有會遺失的修改（這台原本的內容就是雲端的上一版）。還沒有備份時會另存一份，見下方「用雲端的」 |
| 是 | 是 | **衝突**：按「同步」時跳出對話框，讓使用者選「用雲端的」或「用這台的」；自動上傳時只顯示訊息 |

- 「雲端改過」的指紋不包含「（自動計算）」欄和設定裡的 updatedAt，見下方設計決策。

### 第一次連結

- 只有按按鈕時才會連結，自動上傳不會。
- 雲端還沒有試算表：建立一份，上傳這台的資料。
- 雲端的試算表沒有任何資料列（記錄、人員、等級都只剩欄位名稱）：一樣直接上傳，不必詢問。
- 雲端已經有資料（例如在別台裝置連結過）：
  - 內容跟這台一樣：直接完成連結。
  - 不一樣：跳出對話框選擇，並顯示兩邊的記錄筆數和最後修改時間。這台還是示範資料（從沒存過）時，會寫明「示範資料」。
  - 格式壞掉：跳出格式壞掉的對話框，見上方「格式檢查」。
- 什麼時候算連結完成：
  - 雲端沒有資料、直接上傳：寫入成功才算；失敗就維持未連結。
  - 選「用雲端的」：資料換好才算；使用者取消或換資料出錯就維持未連結。換好但寫不進這台（空間不足）時仍算連結，只是不記下雲端的指紋，下次同步會重新拿雲端的。
  - 選「用這台的」：選完就算連結，並標記成還沒上傳；上傳失敗時，下次同步會再上傳。
- 連結期間（上傳還沒完成時）又修改了資料，會標記成還沒上傳，接著自動再上傳一次。

### 對話框的選擇

- **選完之後會再讀一次雲端**：對話框可能開了很久，這段期間雲端又被改過的話，對話框會重新出現，第一行用紅字寫「雲端剛剛又被改過」，顯示最新的內容讓使用者再選一次。避免「用這台的」蓋掉使用者沒看過的修改。
- **用雲端的**：
  1. 先把這台的資料另存到 `grind-log/v1:local-backup`。備份只有一份，可以用「下載這台的舊資料備份」取回。
     - 這台有雲端沒有的資料（衝突時、第一次連結時）：一定存，蓋掉舊的備份。備份存不進去（空間不足）時，先跳確認框，建議先匯出 JSON。
     - 一般下載（這台沒有未上傳的修改）：這台的內容就是雲端的上一版，可以從試算表的版本記錄找回，所以**只在還沒有備份時才存**，不跳確認框。避免衝突時留下的、別處都沒有的備份，被之後一次普通的下載蓋掉。
     - 讀不出原本資料時不存：畫面上是空白資料，原文已經另外備份在 `grind-log/v1:unreadable`。
  2. 再用雲端的資料取代這台。訊息只在真的存了備份時才寫「已另存備份」。
  3. 雲端的資料寫不進這台（localStorage 空間不足）時，不記下雲端的指紋：這台存著的還是舊資料，下次同步會重新拿雲端的。
- **用這台的**：上傳這台的資料，取代雲端。被取代的內容可以從試算表的「檔案 → 版本記錄」找回。
- **先不要**：不同步，維持原狀，之後按「同步」會再問。

### 自動上傳

- 連結後，每次修改約 2 秒後自動上傳，會先照上表判斷。
- 自動上傳**不會跳出任何視窗**，避免使用者打字時被打斷，也避免誤按：
  - 權杖過期時只顯示「有修改還沒同步，按「同步」上傳」。
  - 雙方都改過時只顯示「雲端被別的裝置改過，這台也有修改。按「同步」選擇要用哪一份」。
  - 雲端格式壞掉時只顯示訊息。
- 上傳失敗後，沒有新的修改就不自動重試，避免一直失敗一直重試。
- 開啟頁面時不會自動下載，要按一次「同步」。

### 不能破壞的保護

- **讀不出原本資料（`loadProblem`）的期間絕不上傳**：
  - 這時畫面上是空白資料，上傳會蓋掉雲端。
  - 對話框裡的「用這台的」會停用；「用雲端的」可以用來救回資料。
- **雙方都改過時不會悄悄覆蓋任何一邊**，一定要使用者選擇。
- **格式壞掉的試算表不會拿來取代這台**。
- 雲端的資料換進這台時，走跟匯入相同的 `applyLoaded()`：先試畫，成功才寫入。
- **換掉整份資料時說清楚雲端也會換**：已連結時，匯入 JSON、還原示範資料、清空全部的確認框都會加上「確定後雲端的存檔也會被換掉」。平常不確認的匯入，已連結時也會先確認。

### 中斷連結

- 清掉這台的同步狀態，並撤銷 Google 的存取權限。
  - 撤銷要用還有效的權杖，這是 Google 的規定。所以只有這次開啟頁面後登入過、而且權杖還沒過期（約 1 小時）時才會撤銷。
  - 沒有撤銷時，訊息會請使用者到 Google 帳戶的「第三方應用程式和服務」自己移除。`privacy.html` 也是這樣寫的。
- 同步進行中時按鈕停用，不能中斷。
- 雲端的試算表不會被刪除。之後再連結會找到同一份。
- 雲端的試算表被刪除或移到垃圾桶時，同步會顯示找不到，並提供重新建立。

## 相關程式

`index.html` 的「Google 試算表同步」區段：

- 狀態：`GOOGLE_CLIENT_ID`、`cloud`（同步狀態）、`cloudToken`。
- 登入：`cloudLoadGis()`、`cloudGetToken()`。
- API：`cloudApi()`、`cloudFind()`、`cloudCreate()`、`cloudRead()`、`cloudWrite()`。
- 格式轉換與檢查：`toSheets()`、`fromSheets()`、`sheetHash()`、`sheetProblem()`。
- 同步流程：`cloudSync()`、`cloudLink()`、`cloudStep()`、`cloudChoose()`、`cloudAsk()`、`cloudTakeCloud()`、`cloudPutLocal()`、`cloudMarkDirty()`。
- 在 `persist()` 成功後會呼叫 `cloudMarkDirty()`；換掉整份資料的確認框用 `cloudReplaceWarning()`。

## 設計決策

- **用試算表，不用 JSON 檔**：使用者要能直接在 Google 試算表裡看資料。
- **只要求 `drive.file`**：Sheets API 也接受這個非敏感權限，所以不需要送審，可以開放給所有人使用。
- **開放給所有人**：每個人的資料都存在自己的雲端硬碟。
- **雙方都改過時一定要問**：使用者選的規則，避免任何一邊的修改被悄悄蓋掉。
- **自動上傳**：使用者選的；開啟頁面時仍要按一次，這是 Google 的規定。
- **寫入用單一個 batchUpdate**：先清除再寫入分成兩個請求的話，中途失敗會留下空白或新舊混合的試算表。
- **用內容指紋判斷雲端有沒有改過**：試算表的 Drive 版本號可能延遲更新。
  - 指紋不算 updatedAt：每次存檔都會變，算進去的話一台下載後另一台又會以為雲端被改過。
  - 指紋不算「（自動計算）」欄：只是方便看，小數精度也可能跟寫進去的不完全一樣，算進去會誤判成雲端被改過。
- **自動上傳遇到衝突只提示**：自動上傳是在使用者修改後 2 秒觸發，這時跳出對話框會打斷輸入，預設按鈕也可能被 Enter 誤按。
- **`cloudSeq` 在還沒連結時也要加**：第一次連結時的上傳要靠它判斷上傳期間有沒有新修改，否則那段期間的修改會被誤標成已上傳。

## 修改時要檢查

- 用模擬的 Google API（`tools/make-cloud-test.js`，見 [development.md](../development.md#google-試算表同步)）跑過四種情況：沒改、只有這台改、只有雲端改、雙方都改。另外還要測：
  - 第一次連結（雲端沒有、只有欄位名稱、有資料、格式壞掉），以及連結期間又修改。
  - 對話框開著時雲端又被改。
  - 格式壞掉：改欄位名稱、刪工作表、整份清空。
  - 雲端的資料寫不進這台（覆寫 `Storage.prototype.setItem`）。
  - 試算表被刪除、權杖過期、寫入失敗、登入視窗沒回應。
- `toSheets` → `fromSheets` 來回轉換後，真實資料的內容完全不變，包括未知欄位、`"5%"` 這類認不得的值、停用的記錄。
- 讀不出原本資料時，絕對不會上傳。
- 沒設定用戶端 ID、Electron 版時，整個區塊不顯示，其他功能完全不受影響。
